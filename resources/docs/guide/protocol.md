# 协议规则

请求数据格式：`application/json` 或 `application/x-www-form-urlencoded`（POST 请求体）；GET 查询类接口将认证参数放在 URL query 上

返回数据格式：JSON，统一响应包络

```json
{ "code": 0, "message": "ok", "data": { } }
```

- `code` 为 `0` 表示成功，其它值均为失败，失败原因见 `message`
- `data` 为业务数据，仅成功时返回
- 响应不附带签名：请求认证已覆盖请求方向，响应回传在同一 TLS 连接内；
  安全关键通道是异步通知（Webhook），按订单签名算法签名

签名算法：MD5（未启用 RSA2 时）或 RSA2（商户后台启用后），由必填参数 `sign_type` 指定，
同一时间只有一种算法生效（启用 RSA2 后 MD5 立即失效），签名放在 body 参数内，
详见 [签名算法](/sign/index.html)

字符编码：UTF-8

其它约定：

| 项目 | 说明 |
|---|---|
| 网关地址 | `https://你的网关地址`（下文以 `{site_url}` 表示） |
| 商户ID（pid） | 商户后台「API 信息」页查看 |
| 商户密钥 | MD5：32 位密钥，创建商户即生成，商户后台查看/复制/重置；RSA2：商户自行保管私钥，平台只存公钥 |
| 认证方式 | 每次请求携带 `pid` + `sign` + `sign_type`，且 `sign_type` 必须与商户当前生效算法一致 |
| 时间戳校验 | `timestamp`（Unix 秒）**必填**，与服务器偏差超过 300 秒拒绝（防重放） |
| 下单幂等 | 同一商户同一 `out_trade_no` 重复下单返回原订单 |
| 退款幂等 | 同一商户同一 `out_refund_no` 重复提交返回原退款单 |
| 通知地址 | 下单可传 `notify_url` / `return_url`，缺省时回落商户后台配置的默认通知/回跳地址 |
| 域名白名单 | 平台为商户配置支付域名白名单后，下单请求须携带合法 `Referer/Origin` 且域名命中（支持 `*.example.com` 通配） |
| 频率限制 | 下单接口默认限流 60 次/分钟（平台可调），超限返回失败 |
| 验证顺序 | 商户状态 → 签名与时间戳 → 平台开关（如 API 支付/退款开关） |
| 通道编码 | 参数 `channel_code`：下游指定平台分配的通道编码（如 `8088`），本单只在该编码绑定的通道内分流；**可选**，不传则按平台默认路由分流 |

## 通道编码（channel_code）

平台可以给下游分配「通道编码」，一个编码对应一组上游通道（可以是 1 个，也可以多个），
由平台侧配置随机 / 轮询 / 权重三种分流策略。下游下单时携带 `channel_code`，订单就**只能**
落在该编码绑定的通道内。

- **参数**：`channel_code`，字符串，大小写不敏感（平台统一按小写处理），最多 32 位；
  参与签名（与其它业务参数同一口径，见 [签名算法](/sign/index.html)）。
- **必填性**：**可选**。不携带 `channel_code` 时订单按平台默认路由分流；携带时（建议始终携带）
  只在该编码绑定的通道内分流。平台收银台、收款页与余额充值同样可以不传编码。
- **作用范围**：编码只影响「选哪个上游通道」，不进入上游支付参数，也不改变签名、通知与回跳；
  退款按订单实际使用的通道原路退，与编码无关。
- **重试**：同一 `out_trade_no` 重复下单时，`channel_code` 必须与首次一致，
  否则返回「商户订单号已存在且通道编码不一致」；已拉起过的订单走收银台重试也仍在编码内。

编码不可用时的返回（`code=-1`，HTTP 400，`message` 为下列文案）：

| 情况 | 提示 | 处理 |
|---|---|---|
| 编码不存在 / 编码整体停用 | `通道编码不存在或不可用` | 找平台确认编码，或换用有效编码 |
| 编码与该支付方式没有绑定 | `通道编码不支持当前支付方式` | 改用该编码支持的 `type`，或让平台补充绑定 |
| 编码内成员全部不可用（含临时关闭、限额/限速占满） | `通道编码 8088 当前不可用，请稍后重试` | 稍后用**同一 `out_trade_no`** 重试（订单已保留，`trade_no` 有效） |

编码内某个上游不可用（通道全局停用、限额/限速占满）时，平台会在编码内换下一个可用通道，下游**无感**；
只有编码内全部不可用才报错。平台**不会**在报错时把订单悄悄落到编码之外——编码代表费率与
成本边界，静默越界比失败更难追查。

接入前准备：

1. 商户后台「API 信息」复制 `pid` 与 MD5 密钥即可开始对接（默认 MD5，无需额外配置）；
2. 需要抗抵赖时在「签名方式」中切换到 RSA2：由平台生成密钥对，私钥仅显示一次，请立即保存；
   启用后 MD5 立即失效，接入方必须改用 `sign_type=RSA2`；
3. MD5 订单的通知用同一把 MD5 密钥验签；RSA2 订单的通知用平台公钥验签；
4. 需要指定费率/通道边界时向平台申请通道编码，下单携带 `channel_code`（参与签名）；不携带则按默认路由分流。
