# 协议规则

请求数据格式：`application/json` 或 `application/x-www-form-urlencoded`（POST 请求体）；GET 查询类接口将认证参数放在 URL query 上

返回数据格式：JSON，统一响应包络

```json
{ "code": 0, "message": "ok", "data": { } }
```

- `code` 为 `0` 表示成功，其它值均为失败，失败原因见 `message`
- `data` 为业务数据，仅成功时返回
- 响应不附带签名：请求认证已覆盖请求方向，响应回传在同一 TLS 连接内；
  安全关键通道是异步通知（Webhook），按订单签名算法签名

签名算法：MD5（默认）或 RSA2（需商户后台开启），由必填参数 `sign_type` 选择，
签名放在 body 参数内，详见 [签名算法](/sign/index.html)

字符编码：UTF-8

其它约定：

| 项目 | 说明 |
|---|---|
| 网关地址 | `https://你的网关地址`（下文以 `{site_url}` 表示） |
| 商户ID（pid） | 商户后台「安全设置」页查看 |
| 商户密钥 | MD5：32 位密钥，创建商户即生成，商户后台查看/复制/重置；RSA2：商户自行保管私钥，平台只存公钥 |
| 认证方式 | 每次请求携带 `pid` + `sign` + `sign_type`（`MD5` 默认 / `RSA2` 需开启） |
| 时间戳校验 | `timestamp`（Unix 秒）**必填**，与服务器偏差超过 300 秒拒绝（防重放） |
| 下单幂等 | 同一商户同一 `out_trade_no` 重复下单返回原订单 |
| 退款幂等 | 同一商户同一 `out_refund_no` 重复提交返回原退款单 |
| 通知地址 | 下单可传 `notify_url` / `return_url`，缺省时回落商户后台配置的默认通知/回跳地址 |
| 域名白名单 | 平台为商户配置支付域名白名单后，下单请求须携带合法 `Referer/Origin` 且域名命中（支持 `*.example.com` 通配） |
| 频率限制 | 下单接口默认限流 60 次/分钟（平台可调），超限返回失败 |
| 验证顺序 | 商户状态 → 签名与时间戳 → 平台开关（如 API 支付/退款开关） |

接入前准备：

1. 商户后台「安全设置」复制 `pid` 与 MD5 密钥即可开始对接（默认算法，无需额外配置）；
2. 需要抗抵赖时再开启 RSA2：生成（或上传）密钥对，保存好私钥；
3. MD5 订单的通知用同一把 MD5 密钥验签；RSA2 订单的通知用平台公钥验签。
